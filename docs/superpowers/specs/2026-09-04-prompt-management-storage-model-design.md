# 提示词管理模块调整设计文档（Spec）

> 关联文档：`设计文档.md`（原始产品设计文档，第五节「提示词页面」）
> 本文档范围：仅调整「提示词管理」功能的数据模型与交互，MCP、Skills、Harness 管理、设置等模块不受影响。

---

## 一、背景与问题

现状模型（原文档 5.2 节）假设提示词的编辑主要发生在 Hub 内部，指令文件是库内容的单向导出结果，外部改动是偶发意外，因此设计了「激活前自动回填」兜底。

但实际使用中，指令文件几乎总是被 AI 直接编辑，Hub 只是偶尔打开用来调整 MCP / Skills。每次启动自动导入的机制，把每一次外部改动都当成「新版本」建了一条新记录，导致：

- 库列表被大量无意义的自动条目淹没，真正想收藏复用的提示词被稀释
- 「唯一激活」状态经常与文件真实内容不一致
- 「复制到其他 harness」这个核心功能会带出大量噪音条目

经过评估，确认不需要保留自动变更历史（Hub 非常驻运行，历史价值有限、实现成本不低），本次调整只拆分为两层：**当前内容（live）** 与 **已保存的命名库（saved）**。

---

## 二、调整前后对比

| 维度 | 现状（v1） | 调整后（v2） |
|---|---|---|
| 数据模型 | 单表：多条命名提示词，`isActive` 唯一激活位 | 两层：live（不持久化，运行时读盘）+ saved（命名库，无激活位） |
| 启动行为 | 自动读取指令文件并新建一条库记录 | 不再自动导入，仅作为「当前内容」展示 |
| 「激活」语义 | 持久绑定状态，全局唯一 | 更名为「应用」，一次性写入动作，不产生持久状态 |
| 与文件的一致性 | 依赖 `isActive` 标记，可能与文件真实内容不符 | 运行时按内容比对当前文件与各 saved 条目，实时计算 |
| 删除保护 | 已激活条目禁止删除 | 取消该限制（无持久绑定，删除不影响已写入文件的内容） |
| 覆盖风险防护 | 激活前自动回填外部改动（静默） | 应用前按风险分级显式确认（非静默） |
| 停用行为 | 清空指令文件 | 取消「停用」概念（指令文件不再由 Hub 单方面清空） |

---

## 三、数据模型

### 3.1 当前内容（live）

- **不落库**，每次进入该 harness 的提示词 tab（或点击刷新）时，直接读取指令文件（路径见原文档表格，含「配置目录覆盖」后的实际路径）
- 仅用于界面展示、编辑、发起「另存为」，不是库表中的一行

### 3.2 已保存的提示词库（saved）

```jsonc
// prompts 表，每条记录
{
  "id": "uuid",
  "harnessId": "claude",       // 对应 7 个 harness 之一
  "name": "默认助手",
  "description": "日常开发用",
  "content": "……markdown 内容……",
  "createdAt": 1735900000000,
  "updatedAt": 1735900000000
}
```

相比原模型：
- 去掉 `isActive` 字段
- 「与当前文件是否一致」不入库，运行时用内容比对（逐字节或 hash 均可，量级小，直接比较字符串即可，无需引入 hash 字段）

## 四、页面与交互设计（替换原文档 5.1 / 5.2 / 5.3 节）

### 4.1 布局

```
┌─ harness tab（不变，DSH 置顶）───────────────────────┐
│ 指令文件路径：~/.claude/CLAUDE.md                     │
│                                                       │
│ ▌当前内容                                             │
│  状态：● 与「默认助手」一致   /   ● 自定义内容（未保存）│
│  最后修改：2026-09-03 14:22（读取文件 mtime）           │
│  [ 内容预览（折叠，点击展开全文） ]                      │
│  操作：[ 编辑 ]  [ 另存为新提示词 ]                     │
│                                                       │
│ ▌已保存的提示词                    [ + 新增提示词 ]     │
│  默认助手      日常开发用     更新于 3 天前              │
│    [ 应用 ] [ 对比 ] [ 复制到其他 harness ] [ 编辑 ] [ 删除 ] │
│  精简模式      快速问答用     更新于 2 周前              │
│    [ 应用 ] [ 对比 ] [ 复制到其他 harness ] [ 编辑 ] [ 删除 ] │
│                                                       │
│  （空库状态：提示「还没有保存的提示词」，引导「另存为」/「新增」）│
└───────────────────────────────────────────────────┘
```

### 4.2 当前内容区

- **状态徽章**（运行时计算，不持久化）：
  - 若当前内容与某条 saved 记录的 `content` 完全相等 → 显示「与「XX」一致」
  - 若同时与多条相等（用户自己存了重复内容）→ 显示「与「XX」等 N 条一致」
  - 若与所有 saved 记录都不相等 → 显示「自定义内容（未保存）」
  - 若文件为空/不存在 → 显示「文件为空」，不参与一致性比对（除非存在内容同样为空的 saved 记录）
- **编辑**：Hub 内联编辑当前内容，保存 = 直接写回指令文件（沿用「写入前自动备份 + 原子写入」机制），与 AI 直接改文件是两条并行路径，互不冲突
- **另存为新提示词**：把当前内容固化为一条新的 saved 记录，是「从 live 进入 saved」的唯一入口，完全由用户主动触发

### 4.3 已保存库区

- **应用**（原「激活」按钮更名）：将该条 `content` 写入指令文件，是一次性写操作，不产生持久绑定状态
- **对比**：展示该条内容与当前文件内容的 diff（复用已有的详情/预览面板样式即可），供用户在「应用」前判断影响
- **复制到其他 harness**：交互逻辑不变（见原文档 5.3 节），仅作用于 saved 记录，不涉及 live
- **编辑 / 删除**：不再有「已激活禁止删除」的限制；删除前仍走原有确认对话框；编辑保存后仅更新库记录本身，不联动写入任何 harness 文件

### 4.4 「应用」时的确认流程

替代原来的「激活前自动回填」，改为按风险显式确认：

| 当前内容状态 | 点击「应用」某条目 X 后的行为 |
|---|---|
| 当前内容已与某条 saved 记录一致（含 X 自身） | 直接写入，无需确认（无丢失风险） |
| 当前内容与所有 saved 记录都不一致（存在未保存改动） | 弹确认框：「当前文件有未保存的内容，应用「X」将覆盖它」，提供三个选项：**取消 / 先保存当前内容为新提示词再应用 / 直接覆盖** |

## 五、存储结构变更

### 5.1 data.json schema diff

```diff
  "prompts": {
    "claude": [
      {
        "id": "...",
        "name": "默认助手",
        "description": "...",
        "content": "...",
-       "isActive": true,
        "createdAt": 0,
        "updatedAt": 0
      }
    ]
  }
```

### 5.2 迁移策略

> 项目尚未发版，不存在历史数据，无需旧数据兼容处理（不读取 `isActive`/`enabled`、不做 `createdAt` 兜底、不提升备份导出版本号）。

## 六、对已有功能的影响

- **MCP / Skills / Harness 管理 / 设置**：不受影响
- **5.3 复制到其他 harness**：交互不变，仍只作用于 saved 记录，跨 harness 同步内容始终是用户认可、命名过的内容
- **安全机制（写入前自动备份、原子写入）**：保留不变，「应用」「当前内容编辑保存」两个写文件动作都要经过该机制

---

## 七、边界情况

1. **文件被外部清空或删除**：当前内容显示为空，不视为与任意 saved 记录一致，除非该记录内容本身也是空字符串
2. **多条 saved 记录内容完全相同**：一致性判断可能命中多条，按 4.2 所述合并显示「等 N 条一致」，不强行去重库内容本身
3. **Harness 配置目录被覆盖**（原文档第六节功能）：当前内容区应跟随新路径实时读取，不受本次调整影响
4. **指令文件路径本身不存在（尚未初始化）**：当前内容区显示「未找到指令文件」，「另存为」「编辑」仍可用，保存时创建该文件

---

## 八、验收标准

- [ ] 启动 Hub 不再自动产生新的库记录
- [ ] 修改指令文件后打开 Hub，「当前内容」区能正确展示最新内容和正确的一致性状态
- [ ] 点击「应用」在「无冲突」「有未保存改动」两种场景下分别验证：无确认框直接写入 / 弹出三选一确认框
- [ ] 「另存为新提示词」能正确固化当前内容为新 saved 记录，且不影响原有其他记录
- [ ] 删除任意 saved 记录（包括与当前文件内容一致的那条）不再报错、不再被禁用
- [ ] 「复制到其他 harness」在目标 harness 下产生的是正常 saved 记录，不携带任何一致性/应用状态
