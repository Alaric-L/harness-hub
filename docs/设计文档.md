# HarnessHub — 产品设计文档（最终版）

> 原型实现：`设计原型.html`（单文件可交互原型，含完整使用逻辑）

## 一、产品定位

HarnessHub 是一款基于 Electron 的桌面工具（Windows 安装包），统一管理多个 AI Agent Harness 的 MCP 服务、Skills 与系统提示词。核心解决三个问题：

1. 同一个 MCP/Skill 需要在多个 harness 中重复配置的麻烦
2. 不同 harness 的提示词内容各自独立，缺乏统一查看与迁移手段
3. 直接手改各 harness 配置文件风险高，缺乏统一、安全的管理入口

**支持的 harness（共 7 个，DeepSeek Harness 置顶）**：

| 顺序 | Harness | 配置目录 | MCP 落点 | Skills 目录 | 提示词文件 |
|---|---|---|---|---|---|
| 1 | DeepSeek Harness | `~/.dsh` | `profiles/web/cordis.patch.yml`（YAML patch 插件条目） | `~/.dsh/skills` | `~/.dsh/AGENTS.md` |
| 2 | Claude Code | `~/.claude` | `~/.claude.json`（mcpServers JSON） | `~/.claude/skills` | `~/.claude/CLAUDE.md` |
| 3 | Codex | `~/.codex` | `~/.codex/config.toml`（[mcp_servers] TOML） | `~/.codex/skills` | `~/.codex/AGENTS.md` |
| 4 | Gemini CLI | `~/.gemini` | `~/.gemini/settings.json` | `~/.gemini/skills` | `~/.gemini/GEMINI.md` |
| 5 | Grok Build | `~/.grok` | `~/.grok/config.toml`（[mcp_servers] TOML） | `~/.grok/skills` | `~/.grok/AGENTS.md` |
| 6 | OpenCode | `~/.config/opencode` | `opencode.json`（mcp JSON） | `~/.config/opencode/skills` | `~/.config/opencode/AGENTS.md` |
| 7 | Hermes | `~/.hermes` | `~/.hermes/config.yaml` | `~/.hermes/skills` | `~/.hermes/SOUL.md` |

## 三、MCP 页面

### 3.1 布局

- **矩阵表格**：一行 = 一个 MCP（统一库唯一），每列 = 一个 harness 的开关（toggle）
- 表头为真实品牌图标（hover 显示名称），列宽 80px，表头行高 56px
- 名称列左边距 26px，内容行 hover 显示行操作
- **计数徽章行**（表格上方）：每 harness 一个「图标: 已开启数量」徽章，点击 = 该 harness 全部开启/全部关闭
- **搜索框**（页面顶部）：按名称 / 描述 / 标签 / 命令 / 参数 模糊搜索；无结果时显示空状态提示
- 每行 MCP 名称旁提供 **↗ 链接图标**（打开主页或文档），详情/编辑/删除按钮 hover 显示

### 3.2 交互逻辑

- **开关点击**：立即生效——开启 = 写入该 harness 的真实配置文件，关闭 = 从该配置文件移除
- **新增 / 编辑（单页表单）**：
  - 预设选择（8 个常用 MCP：playwright、fetch、context7、tavily、dbx、filesystem、github、sequential-thinking，一键填充 ID/名称/描述/标签/配置/链接）
  - ID（必填、唯一、编辑时锁定）+ 名称
  - 启用 harness 勾选（默认仅 DSH）
  - 折叠的附加信息：描述 / 标签（逗号分隔）/ 主页链接 / 文档链接
  - 配置 JSON 编辑器（实时语法校验：stdio 必须有 command，http/sse 必须有 url）
  - 「使用向导生成」小弹窗：选择 stdio / http / sse，按字段填写，实时预览 JSON，一键回填表单
- **删除**：确认对话框，确认后从所有启用的 harness 配置中移除
- **从各 harness 导入**：读取各 harness 现有配置合并入统一库（已存在的仅标记该 harness 启用，不回写）
- **详情面板**（右侧可收起）：按 harness 分 tab（图标），展示
  - 启用状态
  - 该 harness 的配置文件路径
  - 写入内容预览（按各 harness 真实格式：DSH 为 YAML patch 插件条目、Codex/Grok 为 TOML、Hermes 为 YAML、其余为 JSON）
  - 主页 / 文档链接按钮

## 四、Skills 页面

### 4.1 数据模型

- **中央 SSOT 目录**为唯一真源（`~/.harness-hub/skills`，随项目更名自原 `~/.harness-manager/skills` 更新），Skill = 目录 bundle（含 SKILL.md，frontmatter 声明 name/description 等）
- 来源：GitHub 仓库安装、skills.sh 安装、ZIP 导入、从各 harness 目录导入未纳管 Skill
- **按 harness 开启** = 将 SSOT 目录中的 Skill 以符号链接（Windows 为 junction，免管理员权限，创建失败直接报错不回退）部署到该 harness 的 skills 目录；关闭 = 移除部署。原「自动」混合模式（已有实体目录复制替换、空位建链接）已从设置收敛下线（主进程分支保留备恢复）
- **共享目录部署目标（`~/.agents/skills`）**：Agent Skills 开放标准的用户级全局目录，作为 Skills 部署的**第 8 个目标（置于 DSH 前）**。开启 = 以同一套 symlink/junction（失败回退复制）管线部署到 `~/.agents/skills/<dir>`；**不支持配置目录覆盖**（标准位置固定）。「哪些 harness 读取该目录」由各 harness 自身决定（如 DSH 同时读取 `~/.dsh/skills` 与 `~/.agents/skills`、同名时专属目录优先），HarnessHub 不追踪该矩阵
- 部署目标数据模型：`SkillTargetId = AgentId | 'shared'`；`SkillInstalled.apps: Partial<Record<SkillTargetId, boolean>>`（data.json 旧数据无 shared 键自然兼容；前向兼容限制：旧版程序读取含 shared 键数据时对含 shared 的条目卸载/开关会报「未知 agent id」）
- **写入前根目录检查**：harness 检查最外层配置目录、共享目录检查 `~/.agents` 根存在（子目录由部署方创建）；任一启用目标缺失则整单拒绝，不产生部分写入

### 4.2 已安装子视图

- 矩阵表格（同 MCP 组件）+ 计数徽章行 + 顶栏搜索
- **部署列 = 7 个 harness + 共享目录（共 8 列，共享置顶）**：共享列头为蓝色文件夹图标，hover 显示「共享目录(~/.agents/skills)」；MCP 矩阵仍为 7 列
- 计数徽章行首为「共享目录」徽章（支持该目标批量开启/关闭）
- 行内信息：Skill 名称、来源仓库或「本地」、可更新标记、描述
- 行操作：详情（SKILL.md 预览 + 各部署目标位置）/ 更新 / 卸载（确认框，卸载前自动备份）
- 顶栏按钮：**检查更新 / 从备份恢复 / 从 ZIP 安装 / 从 harness 导入**

### 4.3 发现子视图

- 来源切换：**仓库**（已配置的 GitHub 仓库）/ **skills.sh**（公共目录）
- 工具栏：搜索框 + 仓库下拉筛选 + 安装状态筛选（全部/未安装/已安装）
- 卡片网格：Skill 名称、仓库徽章、安装量（skills.sh）、描述、查看文档、安装 / 已安装
- 顶栏按钮：刷新 / **仓库管理**（添加仓库 URL + 分支、列出已添加仓库及其 Skill 数、移除）

### 4.4 辅助弹窗

- **从备份恢复**：列出卸载时保留的备份（名称、目录、时间、路径），可恢复（默认不部署）或彻底删除
- **从 harness 导入**：列出扫描到的未纳管 Skill（来源路径 + 发现于哪些部署目标），勾选导入项，并用每部署目标图标开关指定启用范围（7 harness + 共享目录，共享置顶）
  - 扫描范围含共享目录：仅共享命中的条目显示「发现于 共享目录」（`foundIn` 含 `'shared'`）且仅预选点亮共享开关；harness 与共享同名时 harness 路径优先
  - 导入 = 复制入库 + 按所选目标部署（含回写共享目录，原实体目录被部署形态接管）；二级确认对共享目标显示「共享目录」
- 导入弹窗附加交互：
  - **全选/取消全选**单按钮（文案 = 点击后将执行的动作，随列表渲染与手动勾选实时同步）
  - **部署影响提示**：按当前部署方式显示三种文案之一（符号链接 / 复制 / 自动），说明对 harness 内已有同名文件的影响（链接 = 原目录删除后替换为链接；复制 = 原目录整体替换为副本且此后互不联动）
  - **二级确认**：点击「导入选中项」后弹出确认框，含导入数量、目标 harness 与替换警示；仅入库、不部署任何 harness 时为独立文案（不涉及 harness 文件修改）

## 五、提示词页面

### 5.1 布局

- 顶部 harness tab（品牌图标 + 简称，DSH 置顶），切换该 harness 的提示词库
- 每库头部显示该 harness 的指令文件路径 + 「新增提示词」按钮
- 提示词列表：每条 = 激活开关 + 名称 + 描述 + 更新时间 + 操作（复制到其他 harness / 编辑 / 删除）

### 5.2 核心交互

- **提示词库模型**：每个 harness 维护多条命名提示词，同一时刻**仅一条激活**
- **激活** = 将该条内容写入该 harness 的指令文件（映射见第一节表格）；激活前把当前指令文件中的外部改动自动回填到原激活条目，避免丢失
- **停用**：指令文件清空（若没有其他激活条目）
- **已激活的提示词不可删除**（删除按钮禁用并提示先停用）
- **新增 / 编辑表单**：名称（必填）/ 描述 / Markdown 内容，保存按钮；新建条目默认未激活
- 空库状态：提示「还没有提示词」，引导新增

### 5.3 复制到其他 harness（同步）

- 点击「复制到其他 harness」，弹出目标 harness 多选对话框（展示各目标库现有条数）
- 语义：将当前提示词**复制为目标库中的新条目（未激活）**——不影响目标 harness 当前激活的提示词与指令文件；同名条目自动追加序号
- 确认后 toast 提示已复制到的 harness 列表

## 九、技术架构（已按此实现，2026-08）

> 本节的「建议」已全部落地为实际实现：技术栈 electron-vite + TypeScript 主进程 + vanilla JS 渲染层 + vitest 单测 + electron-builder（NSIS）。实现细节与证据修正见 `任务文档.md`。

### 9.1 Adapter 模式

```
统一数据模型（UI 层）
      │
      ▼
 Adapter 接口层
 ├── DeepSeekAdapter    (~/.dsh: YAML patch + SKILL.md + AGENTS.md)
 ├── ClaudeAdapter      (~/.claude.json + ~/.claude/skills + CLAUDE.md)
 ├── CodexAdapter       (config.toml + skills + AGENTS.md)
 ├── GeminiAdapter      (settings.json + skills + GEMINI.md)
 ├── GrokBuildAdapter   (config.toml + skills + AGENTS.md)
 ├── OpenCodeAdapter    (opencode.json + skills + AGENTS.md)
 └── HermesAdapter      (config.yaml + skills + SOUL.md)
      │
      ▼
各 harness 实际配置文件（JSON / TOML / YAML / YAML patch）
```

- 每个 harness 对应一个 adapter（实现于 `src/main/adapters/`）：
  - **读取**：将该 harness 的原生配置格式解析为统一数据模型
  - **写入**：将统一数据模型转换回该 harness 的原生配置格式
- UI 层只感知统一数据模型（经 preload `window.hub` IPC 桥），不感知具体文件格式
- 新增 harness 时只需新增一个 adapter，不改动 UI
- Skills 采用「中央 SSOT 目录 + 按部署目标部署」模型：目标 = 7 harness skills 目录 + 共享目录 `~/.agents/skills`；开启 = symlink/junction（Windows 实测 junction 免特权，创建失败不回退）到目标目录，关闭 = 移除；默认符号链接，「自动」混合模式（已有实体目录复制替换、空位建链接）已从设置收敛，主进程分支保留
- 部署路由实现：`SkillTargetId`（`AgentId | 'shared'`）→ `resolveSkillsTargetDir`（`'shared'` 走 `agentsSharedSkillsDir(env)`，不支持覆盖）→ `assertSkillTargetRoot` 根检查 → `deploySkill`/`undeploySkill`；`toggleSkillOne` 单开关（services/skills.ts，供 IPC 两个 handler 共用）；未纳管扫描 `listUnmanagedSkills` 与导入源定位 `findSourceDir` 均含共享目录
- **格式实现注记**（对齐 cc-switch 实测）：Codex 写显式 `type` + `http_headers`、Grok 不写 `type` 用 `headers`、Hermes 不写 `type` 恒写 `enabled:true`（merge 保留特有字段）、OpenCode `local/remote` 转换、DSH `mcp-<id>` insert 条目；TOML/YAML 写文件采用注释保留策略

### 9.2 数据存储

- **已实现为 JSON 文件存储**（`~/.harness-hub/data.json` + `settings.json`）：MCP 库（含 spec、启用范围、主页/文档链接、标签）、Skills 清单（`apps` 键域为 `SkillTargetId = AgentId | 'shared'`，含共享目录部署开关）、各 harness 提示词库、目录覆盖配置、Skill 仓库；统一经 `src/main/store.ts` 原子读写
- 数据可整体导出/导入为单个 JSON 备份文件（导入前自动创建当前数据快照到 `~/.harness-hub/backups/*.preimport.bak`）

### 9.3 安全机制

- **写入前自动备份**：任何写操作（MCP 开关、Skills 部署、提示词激活/保存）前，先备份目标文件到本地历史目录（`~/.harness-hub/backups`，可关闭）
- **Skill 卸载备份**：卸载时自动保留副本（`~/.harness-hub/skill-backups/<ts>_<slug>/` 含 meta.json，保留最近 20 份），可在「从备份恢复」中恢复或彻底删除
- **原子写入**：先写临时文件校验格式合法性，再替换原文件，避免写入一半导致该 harness 无法启动
- **提示词外部改动回填**：激活提示词前，将指令文件中的外部改动回填到原激活条目（无激活条目时自动创建「原始提示词」备份条目），不静默覆盖
